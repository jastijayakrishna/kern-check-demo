# fix: recover events macOS drops when a watcher starts or stops

**Draft: investigation first, fix to follow in this PR.**

webpack's macOS CI loses a file deletion between watch builds (webpack/webpack#22681, `restored-commonjs-reexport`): no build ever reports it, and the next build reuses the stale module. On Linux the same failure appears only when the deletion event is dropped, never when it is late.

Suspected cause: on macOS, libuv (`src/unix/fsevents.c`) shares one FSEventStream between every directory `fs.watch` handle in the process. Adding or removing any handle destroys the stream and creates a new one from `kFSEventStreamEventIdSinceNow`, so events not yet delivered are lost. watchpack adds and removes handles whenever the set of watched directories changes.

This commit adds a temporary `fsevents-probe` job (macOS, Node 20/22/24) that deletes a watched file, starts another watcher 0–100 ms later, and counts lost deletions, with plain `fs.watch` and with watchpack. It will be removed once the numbers are in.
