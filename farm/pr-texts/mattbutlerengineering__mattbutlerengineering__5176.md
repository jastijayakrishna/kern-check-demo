# ci(auto-review): handle oversized (>20000 line) PR diffs gracefully

Closes #5156

## Summary

`.github/workflows/auto-review.yml`'s "Get changed files" step ran `gh pr diff "$PR_NUMBER" --name-only` with no error handling. Once a PR's diff exceeds GitHub's 20000-line cap, `gh pr diff` hard-fails with `HTTP 406` / `too_large`, which previously failed the whole `Automated PR Review` job -- even though the job's own heuristic checks (large files, console.log, TODO comments, secret patterns) are unrelated to diff *size*. Observed on PR #5117 (~93K/-5K line diff, a legitimate bulk `llms.txt`/`llms-full.txt` regen).

- Extracted the size-vs-other-error decision into a small, pure, unit-tested script: `scripts/gh-diff-failure.mjs` (`isDiffTooLargeError`), following the existing `scripts/ci-gate-commit-status.mjs` pattern (pure function + thin CLI wrapper + workflow-content assertions in the test).
- `.github/workflows/auto-review.yml`'s "Get changed files" step now captures a non-zero `gh pr diff` exit, classifies the failure via that script, and only swallows the confirmed 20000-line-cap case (setting `diff_too_large=true`, exiting 0) -- any other `gh pr diff` failure (auth, network, 404) still fails the job.
- Added a `diff_too_large` output gate: the heuristic "Run review checks" step is skipped when the diff is oversized, and a new "Post diff-too-large comment" step posts a neutral advisory note instead of the pass/fail review comment (does not block merge -- this check is advisory-only, per `.claude/rules/gotchas.md`).
