# Pin the Energy card's height, so it cannot renegotiate it

## Summary

Maintainer instruction, after four fixes missed: *"I'd rather change it and fix the issue, rather than finding the exact cause. It must be possible to make it look the same, but work differently. Like a static size just like header and bottom nav, but moves with the other cards when scrolling."*

**A box that cannot change height cannot oscillate in one.** This removes the degree of freedom instead of hunting for what was moving it.

**Why a height and not a fifth fix.** The card is the confirmed culprit — Energy off ⇒ Home steady, and the flicker follows it into *both* its states. The last reading is why the answer is geometry rather than logic: on a release install Home and this card each rendered **5 times in 45 seconds** while it was visibly unsettled. Whatever moves is not a React re-render, and everything above that layer was already eliminated (`Surface` routes `gap` correctly, both sheets render `null` while hidden, `useEnergyPause` is memoised, `TabSlider`'s handlers dedupe, and the app's only two `withRepeat` animations aren't in this subtree).

**196 is measured, not chosen.** Driven in the web preview at the 430px reference width: the tutorial card settles at **196px** painted (194 content + `Surface`'s 1px edge per side), the live one-meter card at **194**. Pinning to the taller leaves the fresh-install state **pixel-identical** and grows the live card by 2px — and those 2px *are* the renegotiation between its own two states that this ends.

It is a fixed **size**, not a fixed **position**: it stays in the scroll content and scrolls with the cards exactly as before.

## Testing

- `npm run visual` — **23/24 unchanged in BOTH themes**, with the one predicted change (`home-energy-budget`, the 2px). `home-empty` unchanged is the evidence that 196 matched the tutorial state exactly. Diff read before blessing: all four bands present, nothing clipped.
- `npm run geometry` clean · `npm run jitter` clean · `npx tsc --noEmit` clean · `npx jest` **2519 passed**.
- Two existing guards pinned the literal `<Surface style={styles.budgetCard}>`; both now match the *property* rather than the punctuation. A **new** guard pins the height in both branches and was checked to **fail** against an unpinned Surface.
- Re-bless commit holds only the screen that changed; a dozen baselines the run rewrote with 0–663 bytes of rasteriser noise are reverted.

## Two limits, stated rather than papered over

- A fixed height **clips** rather than grows if content ever exceeds it — a longer translation wrapping the legend, or a large text scale. `flexWrap` stays on both rows so nothing overflows sideways, but a wrap now costs the card's bottom. The constant is the knob and is documented as such.
- `energyMode: 'custom'` stacks two meter rows and is genuinely taller. No harness here can reach that state to measure it, so it's left hugging its content rather than pinned to an invented number.

## What this does not claim

Whether it ends the flicker is **unverified from here**, and that trade was made explicitly. If it doesn't, the result is still informative: a card whose height *cannot* change and still flickers is a **paint** problem, not a layout one — which is the next place to look rather than a fifth guess at this one.
