# fix(shader-dsl): renormalize df64_mul between cross terms (Apple collapse)

## What

Restructures `df64_mul` (and `df64_vN_mul`) to renormalize **after each cross term** instead of once at the end — matching the Apple-validated luma.gl / donmccurdy multiply, rather than textbook QD `dd_mul`.

```ts
// before (textbook QD — one renorm)      // after (luma.gl / donmccurdy — renorm per cross term)
prod = twoProd(a.x, b.x)                   prod = twoProd(a.x, b.x)
prod.y += a.x*b.y                          prod.y += a.x*b.y;  prod = quickTwoSum(prod.x, prod.y)
prod.y += a.y*b.x                          prod.y += a.y*b.x
return quickTwoSum(prod.x, prod.y)         return quickTwoSum(prod.x, prod.y)
```

## Why

On-device (iPhone, Apple GPU — both WebGL2 and WebGPU, which Safari both compile to Metal, so they collapse identically) the loaded-lo class is fully fixed by #915/#916, and the **only** remaining failures are the multiply family: `mul` → 0, `vec_mul` → 0, `div` (its Newton step multiplies), `dg_mul*`, and the mul-containing random trees.

`mul` reads **exactly 0** — a *deleted* term, not a mis-rounded one. The driver factors `a·b_hi + a·b_lo → a·(b_hi + b_lo)`, and `b_hi + b_lo` rounds back to `b_hi` in f32, deleting the cross term.

### The dead end this corrects

#917 (reverted in #918) threaded `one` through the cross terms. It **did not work** and **regressed `mul_sq`** (34/61 → 33/61 on-device): `(a.x·b.y)·one` still lets the compiler factor the common `a.x` out, because the guard is on `b.y`, *outside* the common factor. The `one` wall is in the wrong place.

### What the research showed

luma.gl's `mul_fp64` and donmccurdy's Apple-focused [`fp64-arithmetic`](https://github.com/donmccurdy/fp64-arithmetic) both insert a `quickTwoSum` **between** the two cross terms — a deviation from QD made specifically because "Apple optimizes away the calculation necessary for emulated fp64." The intermediate renorm folds each cross term into a fresh guarded `(hi, lo)` pair before the next product forms, so there is no single `a·b_hi + a·b_lo` sum left to factor. `split2` (luma.gl's `HIGH_BITS_OVERFLOW` path) is an Intel-only overflow guard, not the Apple defense — so it is not adopted here.

## Verification
