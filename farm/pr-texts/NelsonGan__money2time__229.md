# Reduce Mixpanel event volume: sampling + disable App Session

## Why

We're on Mixpanel's 1M-events/month free tier but tracking ~60k events/day (~1.8M/month projected). Analysis of a recent day's events showed two dominant, low-signal sources:

- **App Session** (`$ae_session`, Mixpanel automatic) — fired on every foreground; the single largest event (~14.5k/day).
- **Transaction Created / Updated** — core actions, but far too high-volume to send 1:1 (~17k/day combined).

## What changed

**1. Reusable per-event sampling**
`trackEvent` now accepts a third `options` arg: `trackEvent(name, props, { sampleRate })`.
- When `sampleRate` is below 1, the call is sent with that probability and a `sample_rate` property is attached to the event.
- Reconstruct true volume in reporting by scaling the count by `1 / sample_rate`.
- Drop-out happens before the SDK is touched, so sampled-out calls are essentially free.
- Applies to any event — just pass the option.

**2. Sample transaction events to 10%**
`Transaction Created` and `Transaction Updated` now use `TRANSACTION_EVENT_SAMPLE_RATE = 0.1` at all four call sites. Voice transaction creates stay at 100% (low-volume, worth full fidelity).

**3. Disable Mixpanel automatic events (kills "App Session"), keep "First App Open"**
Mixpanel's automatic events are all-or-nothing, so disabling them to drop "App Session" also removes "First App Open". To preserve that signal, a manual `First App Open` is emitted once per install (guarded by a persisted AsyncStorage flag).

## Projected impact

| Scenario | Daily | Monthly |
| --- | --- | --- |
| Before | ~60k | ~1.8M ❌ |
| Transaction sampling only | ~44k | ~1.33M ❌ |
| Sampling + disable App Session/auto events | ~26.5k | ~0.8M ✅ |

## Notes / follow-ups

- "First App Open" going forward is a custom event with the same display name as the retired reserved `$ae_first_open`; historical and new data share the label.
- You lose Mixpanel's built-in session/retention reports — App Store Connect + RevenueCat cover those.
- The `sampleRate` option is now available to throttle other noisy events later (e.g. `Settings Updated`, `Pro Limit Hit`) without dropping the event type.
