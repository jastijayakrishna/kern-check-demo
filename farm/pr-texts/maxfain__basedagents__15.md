# Keyring-first homepage — SPA-shell rebuild (safe Cloudflare Pages routing)

Reinstates the Keyring-first homepage repositioning from #13 (reverted in #14 after it took the site down), rebuilt so the routing is safe on Cloudflare Pages.

## Why #13 broke, and what's different here
#13 made `index.html` a static homepage and moved the SPA to `app.html`, with `_redirects` doing `/* /app.html 200`. Cloudflare Pages rewrites any rule whose **destination is a `.html` asset** to its pretty URL — `/app.html` became a 301 to `/app`, dropping the requested path, so every SPA route bounced to a dead `/app`.

**This PR keeps `index.html` as the SPA shell** — the only safe fallback target, since `/index.html` has no pretty-URL redirect (it's the config that's been live since the revert and pre-#13). The homepage becomes a **React `Home` route** reusing the SPA's stylesheet (styles scoped under `.home` — no collision, no flash). The static leaf pages are served as direct assets exactly like today's working `keyring.html`.
