# Count native layout passes, because the render counters said "not here"

## Summary

The device answered #693's question, and the answer **eliminates the layer four fixes were aimed at**:

```
45s — Home: 5 (0.1/s) · EnergyMeter: 5 (0.1/s)
```

Five renders in forty-five seconds, on a card the maintainer is watching flicker — and Home and the card are *exactly equal*, so the card never re-renders on its own either. **React is static.** There is no re-render storm, and there is no layout loop driven from JS either, because a JS-driven loop would have to re-render to drive it. The memo pass (#682), the fold-gap move (#689) and the flexBasis wrapper (#692) were all aimed at React. The counters are what turns that from a suspicion into a fact.

So whatever moves is **below React**. Two shapes remain, and one is ruled out by a sweep: the only two `withRepeat` animations in the app live in `NewSinceGlow` and `GlowPulse`, and neither is in this card's subtree (`Button`'s breathing halo needs `emphasis && variant === 'primary'`, which this card doesn't use). That leaves **a native layout pass that will not converge**.

This counts those passes directly. `onLayout` fires on the native pass with **no re-render required**, which makes it the only instrument in this codebase that can watch a layout loop from inside the app. Six probes across the card — the outer strip, the tutorial pips, the legend, both `qaLine` wrappers, the live meter's pip line — so the next reading names the **region**, not the screen.

Plus a **control probe** on `HomeNotesCard`: a layout count means nothing alone, since a scroll or a keyboard re-lays out everything. A card on the same screen that doesn't flicker is what makes the Energy numbers readable.

## How to read the next measurement

Settings → Advanced → Debug mode → **Restart counting** → Home for ten seconds → back → **Render counts**.

- `L:notesControl` **high too** → the whole screen is re-laying out; the Energy card is only where it shows.
- One `L:` label **far ahead of the rest** → that region is the loop, and it's a handful of lines.
- **All low** while it still flickers → not layout at all, and the answer is paint/compositing (shadow, gradient, texture) — which would be worth knowing, since nothing so far has tested it.
