# Use native glass on macOS/Windows overlay instead of laggy CSS blur

## Summary
- Overlay's glass panel was laggy because CSS `backdrop-filter` gets recomputed by the webview every frame the desktop behind the always-on-top window changes.
- macOS now uses native `NSVisualEffectView` vibrancy via Tauri's declarative `windowEffects` config, with an automatic upgrade to real Liquid Glass (`NSGlassEffectView`) on macOS 26+ — the crate checks the AppKit version itself, so older macOS just keeps the vibrancy baseline.
- Windows now gets native Acrylic through the same declarative config.
- Linux keeps the existing CSS `backdrop-filter` fallback — there's no portable compositor-level blur primitive across X11/Wayland compositors, same limitation already noted in the codebase for screen-share capture exclusion.
- Frontend skips the CSS blur on macOS/Windows so the native layer isn't fighting a second blur pass.
