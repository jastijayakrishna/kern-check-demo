# 地図の吹き出しにサーバー側の道路状況の推定を出す (FE-08 / BE-16 / BE-18)

## 何を直したか

地図（`components/map/map-canvas.tsx`）は生の投稿を250mメッシュでまとめて色を出すだけで、サーバー側にすでにある推定を一切使っていませんでした。地点をタップしても投稿の羅列が出るだけで、「住民の投稿を集めて、その地点の通行可否を推定する」というこのプロダクトの主張が画面に出ていない状態でした。

- 投稿地点の吹き出しに、**推定された通行可否・確度・根拠・投稿のまとめ・内訳・最終更新**を出しました
  - `roadStatus.list`（BE-16 / `road_status_estimates`）から 通行可否・確度・根拠・更新時刻
  - `reportDigest.list`（BE-18 / `field_report_digests`）から まとめの一文・状態ごとの内訳・報告した人数
- 表示は新しい `components/map/road-status-summary.tsx` に切り出しました
- デモ用データ（`seed-demo-data.ts`）でも推定とまとめを作るようにしました

## なぜそうしたか

**新しいコンポーネントに切り出した**理由は、`components/map/` を触る未マージPR（#36 / #22 / #23）との衝突を減らすためです。`map-canvas.tsx` の変更は「`ReportGroupDetails` に mesh_code を渡し、1行足す」だけに抑えてあります。

**閲覧時に AI を呼びません。** 推定は投稿のときに一度だけ計算されてテーブルに入っているので、画面は保存済みの結果を読むだけです（router 側と同じ方針。閲覧のたびに呼ぶと費用と待ち時間が計算不能になるため）。

**AI が落ちても表示が壊れないこと**を最優先にしました。これはこのプロダクトの主張そのものなので、次の状態をすべて「表示できる状態」として扱っています。

| 状態 | 表示 |
| --- | --- |
| AI が答えた推定 | 通行可否＋確度＋根拠、まとめは「AIの要約」 |
| AI が落ちて多数決にフォールバック | 通行可否＋確度「低い」＋多数決の根拠、まとめは「自動集計」 |
| 推定はあるがまとめが無い（逆も同じ） | 読めた方だけで描く |
| 取得中 | 「道路状況の推定を読み込んでいます」 |
| 取得失敗 | 「道路状況の推定を取得できませんでした」 |
| その地点の推定がまだ無い | 「この地点の推定はまだありません」 |

いずれの場合も、吹き出しに並ぶ投稿一覧（素のデータ）はそのまま残ります。AI 由来かどうかは `is_ai_summary` をそのまま出し分けており、多数決で決まった要約を「AIの要約」と偽りません。

**まとめは地点を指定して1件だけ取ります。** `reportDigest.list` は報告の新しい順に上限で切られるため、地点で絞らないと投稿の多い環境で古い地点のカードが欠けます。吹き出しは開いたときにだけ描かれる（react-leaflet の Popup は開くまで中身をマウントしない）ので、リクエストはタップした地点の分だけです。推定側は地点で絞る入力が無いため、上限まで取ってから選んでいます。

**デモ用データにも推定を入れた**理由は、そうしないとデモで一切見えないためです。デモ用の投稿は `created_at` をずらすために service role で直接 `field_reports` に入れており、投稿API（`fieldReport.create`）の再計算を通りません。そのままだと、発表で開く地図の吹き出しが全部「推定はまだありません」になります。ここでは Gemini を呼ばず（投入が外部APIの調子や鍵の有無に左右されると、発表直前に地図が空になりうるため）、AI が使えないときと同じ多数決（`src/reports/aggregate.ts`）で埋めています。AI 由来ではないことは `confidence: low` と `is_ai_summary: false` で画面に伝わります。片付け（`removeDemoData`）でもこの2つを消すようにしました。

色はすべて `globals.css` のトークンに紐づく utility（`bg-passable` / `bg-caution` / `bg-impassable` / `text-muted` など）で、直書きしていません。

1. 地図タブ（または投稿タブ）で真備町周辺のピンをタップする
2. 吹き出しに、投稿一覧の上に推定のカードが出る（例: 「通行不可 / 確度 低い / 根拠: … / まとめ: 現在は「通れない」とみています。内訳は… / 自動集計・◯/◯ ◯◯:◯◯更新」）

## 残した課題

- **`pnpm test` のバックエンドに、この変更とは無関係な既存の失敗が1件あります。** `seed-demo-data.test.ts` の「架空の家族と投稿が入り、地図が空にならない」で、`fieldReport.list` が `limit: 100` の新着順のため、ローカルDBに他のテストの投稿が溜まっているとデモの投稿が上位100件から押し出されます。この変更を全部戻した状態でも同じように落ちることを確認済みです（DBを作り直せば通ります）。
- `roadStatus.list` は地点で絞る入力が無いため、上限（500件）まで取ってから選んでいます。地点数がこれを超える規模になったら、mesh_code の前方一致を `reportDigest.list` と同じように足すのが素直です。
- 吹き出しを開くまで問い合わせないので、ピンの色そのものは今も生の投稿から決めています。ピンの色を推定に合わせるかは、地図側のPRが落ち着いてからの方が安全だと考えて手を付けていません。
- `AGENTS.md` にある `pnpm tasks:check` は、この環境に Node 24 / mise が無く `.ts` を直接実行できないため走らせられませんでした。代わりに `docs/tasks/all-tasks.md`（9/3 のスナップショット）の FE-08 / BE-16 / BE-18 を読んで進めています。
