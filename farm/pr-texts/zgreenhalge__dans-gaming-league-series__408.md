# feat(discord): weekly match-thread publish + close on score report

## Summary

- `publishWeekThreads()` (`src/lib/discord-threads.ts`) creates one Discord forum thread per match in a regular season's `season-{N}` channel, tagging rostered players by their linked `discord_id` (falling back to their plain name if unlinked). Idempotent — a match that already has a `match_discord_state.thread_id` is skipped, not duplicated.
- Admin-triggered only, via `POST /api/seasons/[id]/discord-threads` (`{ week: number | 'next' }`) — a season's `start_date` is often arbitrary and so is when an admin actually wants a week published, so there's no automatic Sunday-midnight cron. `DiscordThreadPublisher` (wired into `SeasonManager`'s Manage → Season expansion) gives a "Publish Next Week" button plus an arbitrary week-number field, rendering each match's created/skipped/failed outcome immediately.
- `closeMatchThread()` archives + locks a single match's thread once its score is reported — hooked into `PATCH /api/matches/[id]/score` right alongside the existing `notifyMatchScoreReported()` call, with the same "only on the transition into played" gating.
- Every outcome (create success/skip/failure, close success/failure) is recorded to `ops_errors` (`discord_thread_create`, `discord_thread_publish`, `discord_thread_close`) in addition to being returned directly to the caller, since a Discord channel/thread permission problem is the likeliest first-attempt failure and needs to be visible immediately, not just in the admin console's Activity feed on a later page load.
- Docs: `docs/architecture.md` (new API route, `match_discord_state.thread_id` now written not reserved, three new `ops_errors` operations), `docs/glossary.md`, `README.md`'s `DISCORD_BOT_TOKEN` entry (now lists `Manage Threads` alongside the thread-creation permissions it already needed).
- Small drive-by simplifications: `SeasonManager`'s `expandable()`/`canExpand` had drifted into being byte-identical after a gauntlet-eligibility gate was dropped (the row loop now just calls `expandable(s)`); `discord-threads.ts`'s three near-identical "format a non-ok Discord response" blocks collapsed into one `discordErrorDetail()` helper.

Not in this PR: the Discord Scheduled Event → `matches.scheduled_at` time sync-back half of #398 (needs a design call on how to correlate an event to a thread, since Discord doesn't let a scheduled event attach to a text/forum thread natively), and #395's still-unbuilt 1-hour-out reminder.
