# fix(stale-human-blocked): use an allowlist of human-touch event types

Closes #5083

## Summary
- `lastHumanTouchAt()` denylisted only `labeled`/`unlabeled` and counted every other timeline event (`cross-referenced`, `mentioned`, `referenced`, `subscribed`, `connected`, `converted_note_to_issue`) as a human touch. In a repo merging ~27 automation PRs a day, any one referencing an issue silently reset that issue's staleness clock — a real 59-day-idle issue (#3277) was reported as 6 days old and never flagged.
- Replaced the denylist with an explicit, exported, documented `HUMAN_TOUCH_EVENTS` allowlist (`commented`, `assigned`, `unassigned`, `closed`, `reopened`, `renamed`, `milestoned`, `demilestoned`, `marked_as_duplicate`).
- Added actor-based filtering on top of the event-type filter: a `commented` event or an `issue.comments` entry authored by a bot login (`github-actions[bot]`, or any `[bot]`-suffixed login) never counts as a human touch — this also fixes the pre-existing gap where a bot comment reset the clock unconditionally.
- `LABEL_ONLY_EVENTS` is kept exported (existing callers/tests still read it) with an updated docstring noting it's superseded for filtering purposes.
- `buildStaleMetricRow()`'s output shape is unchanged — `metrics/stale-human-blocked.jsonl` run history stays comparable.
