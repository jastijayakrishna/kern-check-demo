# fix(data,playground): bind globalThis.fetch — browser "Illegal invocation" on S-111 (#1333)

## What & why

Bug report: `setCoverageTime` / the live S-111 demo threw `TypeError: Failed to execute 'fetch' on 'Window': Illegal invocation` in a real browser. `#1333`.

Root cause: `const doFetch = opts?.fetch ?? globalThis.fetch` extracts the native `fetch` into a local `const`, then calls it as a bare identifier (`doFetch(url)`). A browser's `fetch` is a WebIDL "legacy platform object" operation that only accepts `this === Window`/`WorkerGlobalScope`; reading it off `globalThis` into a plain variable and invoking *that* drops the receiver, so `this` is `undefined` at the call site and the browser rejects it. Node/Bun's `fetch` has no such branded check, so this was invisible to every test run in this repo so far (all Node/Bun-executed) — it needed an actual browser to surface, which is exactly when it did.

## How it works

Two call sites had the bug; one sibling in the codebase (`map/src/sprite/sprite-atlas-host.ts:73`) was already written correctly and shows the fix:

- `data/src/hdf5/range-reader.ts` `RangeReader.open` — the default `readCoverageRange` hits when no `opts.fetch` is injected. This is what `setCoverageTime`'s range re-read triggers (`map.ts` calls `readCoverageRange(prev._url, {group})` with no `fetch` option).
- `playground/src/examples/s111-mosaic.ts` `installS111Mosaic` — the region-swap fetch. The real `demo-runner.ts` call site passes no `fetch` option, so **every pan-triggered region swap** was exposed to this too, not only time-stepping.

Fix: `globalThis.fetch.bind(globalThis)` at both defaults.
