# Mission Screen UI (Phase 2)

## Summary

Phase 2 of the [Superpowers Mission Loop implementation plan](https://claude.ai/code/artifact/10d3e408-a3db-43c0-af01-c9908c33bd6c) — the actual Mission Screen UI, now that Phase 0/1 (data model, lifecycle logic, evidence bridge) is live and hardened via #37/#58.

`MissionTab.tsx` is now the app's first and default tab, implementing all five areas from spec §4:

- **Right Now** — the Primary's next action, or an empty-state prompt.
- **Primary Mission** — finish line, blocker report/unblock, capacity-mismatch report, evidence-gated completion (a confirmation checkbox + evidence detail are both required before "Mark Completed" is even clickable), pause/abandon, and a two-step priority-challenge flow: "Preview challenge" shows the recommendation, a separate "Apply" click is required to actually replace the Primary — it never happens silently.
- **Secondary Mission** — collapsed by default; only offers a promote action once Primary is genuinely Blocked or a capacity mismatch is on record, matching the reducer's own gating.
- **Parked** — set a finish line on any Parked/Candidate mission to make it Primary-eligible; a "New mission" form for capturing a fresh one with a title/why.
- **Capture Idea** — writes directly to `nd_captures`, Parked by default.
- **Evidence Status** — reads `evidence_snapshots` for the Primary via the Phase 1 `evidence.ts` helpers (`groupByMission`/`hasConflict`/`isStale`), with an honest empty state.

Every mutation goes through one `applyAndPersist` helper: the `missionLoop.ts` reducer runs first, the board updates optimistically, and any Supabase write failure rolls the board back to its pre-action state rather than letting the UI drift from what's actually saved (spec §8's "preserve the previous record" rule).

## Two things I deliberately did NOT do in this pass

1. **Capture pipeline unification (spec Phase 3).** `ControlsTab.tsx`'s capture-to-`nd_captures` logic is working, tested-in-production code. Rather than blindly refactoring it into a shared hook in the same pass as new UI, `MissionTab`'s Capture Idea writes to `nd_captures` directly with the same shape. Unifying both call sites into one hook is the clean next step, not bundled here.
2. **Evidence bridge → Supabase gap.** `evidence_snapshots` will show an honest "no evidence yet" state indefinitely right now, because `scripts/evidence-bridge.mjs` still writes a `public/notes/evidence-snapshot.json` file (the original biometrics-style contract) rather than upserting into the table the RLS policies were actually designed around. This is a real, contained follow-up — flagging it rather than quietly leaving Evidence Status pointed at a table nothing writes to.
