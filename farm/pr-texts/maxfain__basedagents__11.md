# feat(start): web "Get started" door — terminal-primary, email look, agent-command finish

Implements the `/start` web door from the updated onboarding redesign (§2) and keyring page-copy v1 — a second, secondary door to the terminal-first onboarding for people who want to start in a browser.

**Scope decision (confirmed):** terminal-primary, an email "look" door, and a **first-time finish that hands the user the command to give their agent** — never a raw terminal instruction. There is deliberately **no browser-side vault**: setup always happens where the agent lives, so the vault private key never enters a browser.

## `/start` — one page, two doors
- **"I'm at my terminal"** (default): the paste-into-Claude-Code block + `npx @basedagents/keyring init`.
- **"Start in your browser"**: one email field, no password → magic link.
- **Finish:** a **returning** account gets a look session → `/home`; a **brand-new** email gets no session and the console shows the command to paste to its agent.

## Control plane (`packages/api`)
- `POST /start/email` — magic link to *any* address (uniform text, no enumeration), rate-limited 3/min.
- `POST /start/finish` — `{has_account:true}` mints a look session; `{has_account:false}` for a first-time visitor (no session).
- magic-link `purpose` widened to include `'start'`.
