# feat(leaderboard): rank regular-season leaderboards by wins instead of WR%

## Summary

- `canonicalSort()` in `src/lib/util.ts` now orders **Wins → RWR% → ADR** instead of WR% → RWR% → ADR. It's the single ranking function behind regular-season rank, medal/trophy determination, gauntlet seeding projection, per-map leaderboards, and OG share cards, so the new order applies consistently everywhere it's used.
- `LeaderboardTable`'s existing **W-L** column now drives the default/canonical sort (tiebreak RWR% then ADR) instead of adding a duplicate wins column — the WR% column is untouched and still sorts by rate when clicked directly.
- Replaced three hand-rolled duplicates of the old WR%→RWR%→ADR comparator that had drifted from `canonicalSort()`, bringing them onto the same wins-first order: the `/seasons` podium in `podiumSort()` (now calls `canonicalSort()` directly, which also fixes a pre-existing missing-ADR-tiebreak gap), `PlayerView`'s per-player map-stats table, and `aggregatePlayerStatsByMap()` in `src/lib/player-stats.ts`.
- `getSeasonMetaLeaderboard()` in `src/lib/seo/og.ts` now selects `matches_won` so its OG-card ranking stays on `canonicalSort()`.
- Updated `CLAUDE.md`, `docs/calculations.md`, `docs/glossary.md`, `docs/recipes.md`, and stray comments in `src/lib/queries/trophies.ts` to describe the wins-first order as current behavior, and removed a glossary line claiming the site ranks by rate-based stats rather than win totals (no longer accurate).
- Gauntlet ranking (`canonicalGauntletRankMap()` in `src/lib/gauntlet-ranking.ts`) is a separate, deliberately win-rate-based ranking and is untouched by this change.
