# refactor(checkin): one check-in system, not four

Removes Kiosk Mode, and with it the three other ways to check a member in that had accumulated alongside the QR scanner.

## What was there

Four check-in paths, all writing the same `attendance_logs` rows:

| Path | What it was |
|---|---|
| `/checkin/qr-scanner` | nav "Check In", the Quick Action, target of the printable client QR card |
| `/checkin/kiosk` | identical jsQR loop against the identical `POST /api/qr/scan` — differed only in chrome (fullscreen, clock, idle logout) |
| `/checkin/mark` | GPS + fingerprint, in no nav group and no search index — reachable only by typing the URL |
| Attendance Records' biometric panel | fingerprint check-in and member-code entry, on the records page |

The same visit could be recorded by four routes and the difference reconciled by hand. Two of them could not have worked for a new member in any case: nothing in the frontend ever called `memberWebauthn.registerBegin`, so no one could enrol a fingerprint through the UI in the first place.

## What stays

`/checkin/qr-scanner` — the one way in. `/checkin/dashboard` stays too; it reads stats and checks nobody in. Attendance Records keeps its manual present/absent marking and its live feed, which the removed panel was merely also rendering a three-row preview of.

**Explicitly untouched:** `/admin/biometrics` and `/api/auth/webauthn`. That is staff passkey *login*, a different system that happens to share the word.

## Notes for review

`src/app/api/webauthn` and `src/app/api/biometric-attend` — twelve Next route proxies — were found by the new test, not by grepping for the API client names. That is why `single-checkin.test.ts` walks source files for the dead endpoint strings rather than trusting imports.

Merge this **before** the matching backend PR: this removes the callers, that one removes the endpoints. The reverse order leaves live screens pointed at routes that no longer exist.

## Follow-up, not in this PR

`/checkin` is still in the middleware's public-prefix list, which existed for the unauthenticated kiosk. The QR scanner has its own `<Guard>`, so that exemption can now be dropped — but it is a security change beyond the ask and belongs in its own PR.
