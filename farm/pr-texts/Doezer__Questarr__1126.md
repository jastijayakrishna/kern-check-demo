# Fix ssl.redirectHttp never redirecting HTTP to HTTPS

## Description

Before: with `ssl.enabled` and `ssl.redirectHttp` set, the server logs "HTTP to HTTPS redirection is ENABLED", yet plain HTTP keeps serving the app. The redirect middleware was added with `app.use` after the HTTPS server started, which is behind the SPA catch-all and every route, so no request ever reached it. Separately, with `QUESTARR_BASE_PATH` set, the HTTPS listener served the un-mounted `app` rather than the app under the base path.

After: `http://host:5000/library?x=1` answers `302 https://host:<ssl port>/library?x=1`, and `/api/health` stays reachable over HTTP for container health checks. HTTPS serves the same tree as HTTP, base path included.

**How**
- New `server/https-redirect.ts` holds the same redirect logic, with the hostname validation that prevents an open redirect.
  - `index.ts` installs it before `registerRoutes`, and it stays a no-op until the HTTPS server is listening.
  - It redirects with `req.originalUrl` instead of `req.path`, so the base path and query string are kept.
  - Requests already marked secure pass through, including `X-Forwarded-Proto: https` when `trust proxy` is set.
- `index.ts` captures the root request handler returned by `registerRoutes` before Socket.IO wraps the server, and gives it to `https.createServer`.
- The `sca-scan` fix from #1124 (engine.io, brace-expansion and fast-uri overrides) is ported here, because `main` currently fails that check. The commit becomes a no-op once #1124 merges.

**Tests**
- `server/__tests__/https-redirect.test.ts` covers:
  - no-op until enabled;
  - redirect with path and query, ahead of an SPA-style catch-all;
  - health check exempt;
  - malformed Host falls back to localhost;
  - base path kept;
  - forwarded HTTPS passes through.
- I also checked by hand with a self-signed cert and `redirectHttp: true`: `main` answers 200 on HTTP, and this branch answers `302 https://localhost:5444/library?x=1`. Health checks answer 200 on both, and Socket.IO polling works over HTTPS.

No UI change.
