# fix(core): Require trigger node name for MCP workflow executions

<!-- CURSOR_AGENT_PR_BODY_BEGIN -->
## Summary

`execute_workflow` no longer starts the first MCP-supported trigger with empty defaults when the caller’s inputs do not match that node. It now requires an explicit `triggerNodeName` whenever `inputs` are provided, and webhook / chat / form payloads must match the named node.

- Drop `inputs.type`. The payload shape is inferred from the named trigger.
- `triggerNodeName` is a sibling of `inputs` (same pattern as `test_workflow`).
- If neither is provided, the workflow must have exactly one no-payload trigger for the mode (Schedule, or Manual in manual mode).
- `get_workflow_details` trigger notices now document `triggerNodeName` and the correct `formData` object shape.
- Trigger lookup is shared with `test_workflow` via `findEnabledEligibleTrigger(s)`. `test_workflow` keeps its first-trigger fallback; `execute_workflow` does not use that fallback.

This is a breaking MCP schema change for clients that sent `{ type, chatInput | formData | webhookData }` without `triggerNodeName`.

## How to test

1. Create a workflow with a Webhook trigger (and optionally a Chat Trigger after it). Mark it available in MCP.
2. Call `execute_workflow` with chat inputs and no `triggerNodeName` — expect an error, not `status: 'started'`.
3. Call `execute_workflow` with `triggerNodeName` set to the webhook node and `inputs: { webhookData: { body: { hello: 'world' } } }` — expect `status: 'started'` and the body to appear in the execution.
4. Call `get_workflow_details` and confirm trigger notices include `triggerNodeName` and `formData` as an object, not an array.
5. A schedule-only workflow should still execute with neither `triggerNodeName` nor `inputs`.

```bash
pushd packages/cli && pnpm test src/modules/mcp/__tests__/execute-workflow.tool.test.ts
pnpm test src/modules/mcp/__tests__/test-workflow.tool.test.ts
pnpm test src/modules/mcp/__tests__/mcp.utils.test.ts
pnpm test src/modules/mcp/__tests__/webhook-utils.test.ts
popd
```
