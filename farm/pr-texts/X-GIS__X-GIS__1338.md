# feat(map): black outline on the S-111 arrow field (#1333)

## What & why

Follow-up to the S-111 conformance audit — the vendored catalogue strokes every `SCAROW0N` arrow symbol with a black outline (`SVGStyle_S111day.css` `.sCHBLK {stroke:#000000}`, 0.32mm) around its band-coloured fill. That was the one remaining gap flagged in the audit table. `#1333`.

## How it works

The `ArrowDrawSpec` primitive has no native stroke (solid fill only — confirmed against `graphics-types.ts`). So the outline is a **second, larger, black compiled-arrow batch drawn UNDER the coloured fill**: the retained-arrow draper has no depth test (pure alpha blend, `graphics-manager.ts` `renderRetained`), so draw order IS stacking order — `addCoverageArrowShowLayer` now pushes the outline batch first, the fill batch second, both at the same position/bearing.

- `map/src/render/s111-portrayal.ts`: `S111_OUTLINE_COLOR` (black), `S111_OUTLINE_STROKE_PX` (a constant px delta, not the catalogue's literal mm-proportional ratio — 0.32/11mm ≈ 2.9% is sub-pixel and invisible at the smallest on-screen bands (~14px); same screen-legibility tradeoff already made for `S111_ARROW_BASE_PX`, documented inline), `s111ArrowOutlineLengthPx`.
- `map/src/coverage-arrow-show.ts`: emits both batches. **Verified on the real CBOFS cell**: 69,739 arrows per batch, outline black `[0,0,0,1]`, size exactly `+3px` (2×1.5) over the fill at every band.
