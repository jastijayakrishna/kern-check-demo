# Set up Sentry error monitoring (env DSN, PII-safe)

## Summary

Wires `@sentry/react-native` for crash/error reporting, hardened for a finance app. Builds on the Sentry setup-wizard scaffolding, with the changes below layered on and the hard-coded DSN removed from history.

## What changed

- **DSN via env, not committed.** `Sentry.init` now reads `process.env.EXPO_PUBLIC_SENTRY_DSN` instead of a hard-coded string. When the var is unset, Sentry no-ops rather than crashing. The wizard's original commit (which contained the DSN inline) was rewritten out of the branch history.
- **Privacy defaults flipped.** `sendDefaultPii: false` and **Session Replay removed** (`mobileReplayIntegration` + replay sample rates) so no financial data, screen recordings, IP, or PII leave the device.
- **Event hardening (`services/errorReporting.ts`).** `beforeSend` / `beforeBreadcrumb` hooks that:
  - dedupe identical errors and cap volume per rolling 5-minute window (so a render loop can't burn the Sentry quota),
  - scrub the user down to an anonymous id and strip request payloads,
  - drop `console` breadcrumbs (which can carry logged financial data).
  - Pure and unit-tested — `__tests__/services/errorReporting.test.ts` (9 cases).
- **Build wiring** (from the wizard, retained): Metro uses `getSentryExpoConfig` for source maps, the app is wrapped with `Sentry.wrap`, the Expo config plugin is registered, and a dev-only "Throw test error" tile is available in Settings.

## Follow-up (manual, outside this diff)
