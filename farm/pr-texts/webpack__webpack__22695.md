# fix: keep earlier stats readable after their modules are cleaned up

**Summary**

Reading the stats of an earlier build can crash with `TypeError: Cannot read properties of undefined (reading 'getSize')` once a later build has rebuilt one of its modules and the build after that no longer has it. `NormalModule#cleanupForCache` caches each source type's size before dropping the generator, but not the total size, which stats ask for without a type (`module.size()`), so `size()` falls through to the dropped generator.

This is the failure in macOS CI on #22693 (`WatchCacheUnaffectedTestCases › plugins › mini-css-extract-plugin › 1 should allow to read stats`); macOS hits it more often because its lost watch events make the harness re-touch files, which adds rebuilds.

The fix caches the total size too, alongside the per-type sizes.

**What kind of change does this PR introduce?**

fix

**Did you add tests for your changes?**

Yes. `test/unitCases/Watch.unittest.js` runs three builds with a memory cache: the second rebuilds a module the first build's stats hold, the third no longer includes it, then the first stats are printed. It throws the `getSize` error without the fix and passes with it.

No.
