# feat(pii): audio redaction — PII spans to timestamp windows to duration-preserving mute/bleep, content-addressed redacted variant, separable re-transcribe verify (Part of #14807)

Part of #14807 — the audio-redaction core: span production, duration-preserving mute/bleep execution, content-addressed redacted-variant storage, and the separable re-transcribe-verify contract. Residuals (sibling-owned or follow-on wiring) are listed explicitly at the bottom.

## What this adds

**Span production — `@elizaos/shared/audio-redaction` (pure, browser+node safe)**
- `matchPiiSpansToWords`: text-PII verdicts (the `span` strings from tier-0 detectors / `PII_SCRUB` verdicts, with optional pseudonym labels from #14805 accepted as plain input) are located inside **raw timed-ASR word spans** (`TranscriptWord` — no dependency on #14806's unlanded anchor seam). Matching is separator-insensitive in both directions: `"John Smith"` across two ASR words and `"555 0123"` inside one fused ASR word `"5550123."` both match; **every** occurrence is windowed. Unlocatable PII returns in `unmatched` — the caller must fail typed (fail-closed, per @LauraGPT's acceptance note); it is never silently empty.
- `mergeRedactionSpans`: pad → clamp to `[0, duration]` → merge overlaps/adjacency/containment into non-overlapping integer-ms windows; malformed spans **throw** rather than drop. Default pad is **250 ms, empirically calibrated** (see evidence: at 150 ms a boundary digit fragment of the planted phone number survived; at 250–300 ms nothing PII-shaped survives re-transcription).

**Execution — `packages/agent/src/api/audio-redaction.ts`**
- **Pure-TS PCM16 WAV lane** (every runtime, no ffmpeg): sample zeroing (mute) / phase-anchored 1 kHz sine (bleep). Byte geometry untouched, so duration is preserved **exactly** and output is **bit-deterministic**. This covers the voice pipeline's native 16 kHz PCM16 WAV with zero dependencies — the constrained-runtime criterion.
- **ffmpeg lane** (desktop/server only) for ogg/opus, m4a/aac, mp3, webm using the issue's empirically verified graphs — `volume=0:enable='between(t,S,E)+…'` (mute), `sine=f=1000` + gated `amix=duration=first:normalize=0` (bleep) — with `-bitexact` for deterministic bytes. Per-container duration assertions: wav+ogg exact (±2 ms probe slack), aac/mp3 ±(1024/sampleRate)s (one encoder frame); drift beyond tolerance throws `AUDIO_REDACTION_DURATION_DRIFT`. A lossy container on a host with **no ffmpeg** (mobile/workers) throws typed `AUDIO_REDACTION_UNSUPPORTED` — observable, never a silent skip.

**Storage — `packages/agent/src/api/audio-redaction-store.ts` (#8876-clean)**
- The redacted variant is **a second object in the ONE content-addressed media store** (`persistMediaBytes` → `${STATE_DIR}/media/<sha256'>.<ext>` served at `/api/media/<sha256'>.<ext>`). No new store, no files table, no `fileId`, no refcount engine. Job key `pii-audio:<originalSha>:v<ruleset>:<mode>:<spanHash>` (the audio analog of the #14808 `pii:<sha>:v<ruleset>` marker). A small capped memo (`audio-redactions.json`, the `background-pins.json` precedent) makes re-runs cheap lookups — it is a cache, not truth: wiping it recomputes to the **identical output sha** (tested). `media-store.ts` gains two additive exports (`storedMediaFileExists`, `mimeForStoredMediaFile`); nothing else in the store changes.

**Verify — `@elizaos/shared/audio-redaction-verify` + agent adapters, deliberately SEPARABLE from the span producer** (per the acceptance note):
- `RedactionTranscriber` contract: audio bytes + language hint in, normalized transcript out, **no timestamps required**.
