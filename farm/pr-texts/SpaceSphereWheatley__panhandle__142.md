# Cap the desktop app frame to a 2:1 ratio, centered in the viewport

## Summary
- The desktop frame added in 1.22.2 always stretched `#root` to fill the full viewport height (`min-height: 100vh`), so on a wide *and* tall browser window it read as an oddly elongated column instead of a phone-like app.
- The frame is now capped at 480×960 (a 2:1 height:width ratio) via `aspect-ratio`/`max-height: 100vh`, and centered on both axes with a flex body — shrinking further only if the window itself is shorter than that.
- Giving `#root` a `transform` makes it the fixed containing block for its `position: fixed` descendants (TabBar, Fab/FabMenu, Sheet overlays, toast), so they track the frame's edges instead of the raw browser viewport now that the frame doesn't always fill it.
- That containing-block change broke two assumptions written for a viewport-sized frame: Fab/FabMenu's `right` offset used a `50vw`-based hack to reach in from the *viewport's* edge to the centered column, and Sheet's bottom-sheet modal used `88vh` for its max height. Both are now expressed relative to the frame itself (a `--fab-right` CSS variable overridden inside the frame breakpoint, and `88%` instead of `88vh`), so they hold up whether the containing block is the viewport (mobile/tablet) or the capped frame (desktop).
- Version bump to 1.22.3 + changelog entry per repo convention.
