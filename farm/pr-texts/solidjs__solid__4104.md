## Summary

Before: the JSX hello world (`app: compiled floor`) shipped 10,352 B brotli and had been over 10 KB since we added it on Oct 5. The hand-written floor (`render + one signal`) crossed 10 KB today with #4085 (9,994 → 10,156 B) and sat 1 B over its cap on `next`.

After: the JSX hello world ships 9,752 B (−600 B) and the hand-written floor ships 9,549 B (−622 B). The signals core floor goes from 7,657 B to 7,238 B. Behavior doesn't change, and there's no new public API.

The bundler's minifier can remove a module-level `let x = null` that nothing assigns, along with every check on it. It can't do that for `GlobalQueue._x` statics, which is how the optional engines plugged in until now.

How:
- **signals:** the 21 `GlobalQueue` hooks the floor reads become module variables in `scheduler.ts`. Each engine (lanes, verdicts, boundaries, store, affects, external source) sets its own through an `install…Hooks()` function when it loads. Code that only lanes or verdicts can reach is gated on that engine being installed: the lane seat and staging in `recompute`, lane and pending-flight reads in `read`, the lane write in `setSignal`, `propagateStatus`'s lane step, `stagedReaders`, `stagedScreen`/`frameRead`, and the settle step's zombie re-run loop. Without those engines, the gated state can't occur: only `lanes.ts` (and `store/optimistic.ts` through it) sets lane state, and only `verdict.ts` sets the verdict flag. The dead `untrack` fast path is removed. It compared `_externalUntrack === null` against a static that was always `undefined`, so it never ran.
- **web:** client-only `render` no longer keeps hydration text adoption in `normalize`, which is now gated on the hydration runtime that only `hydrate()` installs. `eventHandler` drops guards that no caller needs. `reconcileArrays` reuses `isLive` for its ownership checks. `selectInsert` moved so the minifier can remove it.
- Caps are ratcheted down (lower only), so the savings don't erode silently.

Three pages that load every engine move slightly the other way, because brotli compresses the smaller web code a little worse there:
- `page: live server components`: +92 B brotli, −1 B minified. It's now 43 B over its cap, but within its recorded minified (+4 B), so the gate warns rather than fails.
- `live + router` and `compiled live`: already over their caps on `next`, and they move +43 B and +13 B.

## How did you test this change?

- Prettier is clean.
