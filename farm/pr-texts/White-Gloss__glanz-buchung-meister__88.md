# Phase 21: Kundendaten aus dem Serverprotokoll halten

## Ausgangsproblem

Phase 21 verlangt nachvollziehbare Ereignisse **und**: „Logs dürfen keine unnötigen sensiblen Inhalte enthalten." Die zweite Hälfte hielt nicht.

## Ursache

Serverseitiger Code protokollierte rohe Fehlerobjekte:

```ts
console.error("[mail] Versand übersprungen:", error);
```

Node gibt bei einem `Error` auch dessen eigene aufzählbare Eigenschaften aus. Der PostgreSQL-Treiber hängt `detail` an — bei einer verletzten Eindeutigkeit steht dort wörtlich:

```
Key (customer_email)=(max@example.de) already exists.
```

`db.server.ts` reicht Treiberfehler unverändert weiter (`pool.query` ohne eigenes `catch`), die Aufrufer geben sie ins Protokoll. Dasselbe gilt für HTTP-Fehler von Mail- und ERP-Diensten, die die Empfängeradresse zurückspiegeln.

## Lösung

`src/lib/serverLog.ts`: ein Fehler wird auf **Name und Meldung** eingedampft, gekürzt, und was nach Adresse, Telefonnummer oder Schlüssel aussieht, wird ersetzt.

**Die Rechnungsnummer bleibt ausdrücklich stehen** — sie ist der Griff, mit dem ein Vorgang im Protokoll wiederzufinden ist. Eine erste Fassung meines Telefonmusters hat sie gefressen (`WGD-2026-17` sieht wie eine Nummer aus); der Test dazu hat es gefangen, das Muster schließt den Bindestrich jetzt beidseitig aus und zählt Ziffern.

Für die allgemeine Serverfehlerbehandlung gibt es `protokollAusnahme` **mit** Aufrufweg — dort ist der Stack die Diagnose, er wird aber zeilenweise mitredigiert.

## Betroffene Stellen

Beide Auffangstellen in `src/server.ts`, die Sitemap-Route, sowie die Mail- und Benachrichtigungspfade in Buchungen, Zustandsmeldungen, Dellen-Anfragen und Meta CAPI.

**Nicht angefasst:** browserseitige Fehlerbehandlung (`__root.tsx`, `bookingSuccess.ts`). Dieses Modul ist für das Serverprotokoll.

## Bekannte Restrisiken

- Die Redigierung arbeitet mit Mustern. Sie ist bewusst großzügig, kann aber eine ungewöhnlich formatierte Angabe übersehen. Sie ersetzt keine Sorgfalt beim Formulieren von Meldungen.
- Die Zeilen gehen weiterhin ins Prozessprotokoll des Servers. **Der Betrieb sieht sie im Adminbereich noch nicht** — eine dauerhafte Ablage mit Ansicht ist der nächste Schritt und baut auf dieser Form auf.
- Ob das Protokoll auf dem IONOS-VPS eingesammelt und aufbewahrt wird, ist von hier aus nicht prüfbar.
