# feat(compiler): rgb/rgba/hsl/hsla data-driven channels — runtime colour-constructor builtins (#777)

## What & why

Dynamic colour constructors — `["rgb", ["get","r"], …]`, `["hsl", …]` — were **dropped at conversion** (`rgbHandler` warned + returned null; `hsl`/`hsla` had no handler) and the evaluator's `callBuiltin` had no case (threw → fallback). Now they emit a runtime `rgb(…)`/`hsl(…)` call the evaluator resolves per-feature to hex. Flips the `rgb / rgba` and `hsl / hsla` spec-coverage rows **partial → supported** (supported 181→183, partial 19→17). Part of the #777 Mapbox style-spec gap.

## How it works

- `expr-string.ts` — `rgbHandler` non-constant branch now emits the call (recurses channels); new `hslHandler` mirrors it (constant → hex via `resolveColor`, dynamic → `hsl()`/`hsla()`).
- `expr-registry.ts` — register `hsl`/`hsla` → `hslHandler`.
- `evaluator-helpers.ts` — `rgb`/`rgba`/`hsl`/`hsla` `callBuiltin` cases (hex output byte-matches the converter's constant encoding) + `BUILTIN_FN_NAMES`. Per-feature-CPU path (`rgb` ∉ `GPU_SAFE_BUILTINS`).
- `validate-fncalls.ts` — the four constructors move from `NON_BUILTIN_CALLEES` to genuine builtins (validation-neutral).
- `spec-coverage/expressions.ts` — the two rows flip; `scripts/gap-matrix.md` regenerated (byte-matches the generator).
