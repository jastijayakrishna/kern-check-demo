# fix(map,rhi): WebGL2 tile-swap flicker — mirror render()'s fallback-ancestor pass into the twin (#1046)

## What & why

On the WebGL2 backend, tiles **flicker** during a pan/zoom swap: a newly-needed tile shows the background for ≥1 frame. Root cause (confirmed, code + visual): the production WebGL2 frame is the hand-maintained twin (`render-loop.ts:260` → `renderFrameViaRhi`; `_chainRunsOnWebgl2=false`), whose `renderFillsRhi`/`renderLinesRhi` draw primaries **"minus fallbacks"** and upload missing tiles async — so a non-resident tile draws *nothing* in its place, while the WebGPU `render()` path draws a coarse fallback ancestor there.

This is the sanctioned **"patch the twin first for live bugs"** pattern (#1046) — **#1046 F3 (route WebGL2 through `render()` and delete the twin) is the durable follow-through** that makes this coverage inherited-for-free.

## How it works

Mirror `render()`'s fallback-ancestor machinery into the twin's fill + line paths:
- **`collectTwinFallbacks`** reuses the pure, backend-blind `classifyTile` to build a fallback-ancestor list for every not-yet-resident tile, **synchronously uploaded** (`doUploadTile`/`uploadSync`) so it is drawable this frame.
- **Stencil-masked fallback pass**: primaries write `setStencilReference(1)` where they draw; fallbacks draw at `setStencilReference(0)` (test == 0), so a fallback fragment can never double-draw over a primary — each `clip_bounds`-clipped to the visible tile it covers (mirrors `render()`'s stencil fallback pass).
- **`stableKeys = neededKeys ∪ fallbackKeys`** so `beginFrame` eviction protects the visible set on WebGL2 (the twin never set it — a secondary amplifier).

**Key deviation from `render()` — new `RhiRenderPass.clearStencil()`** (`rhi/src/rhi.ts` + both backends). Root cause found during verification: the twin draws *all* shows in ONE screen pass, so the full-screen synthetic-background primary leaves `stencil=1` across the frame, masking *every* later show's fallback to nothing. WebGPU avoids this via per-sub-pass `stencilLoadOp:'clear'`; the single-pass twin needs a mid-pass stencil clear (WebGL2: `gl.clear(STENCIL_BUFFER_BIT)`, scissor-disabled + unmasked; **WebGPU: no-op** — the twin is WebGL2-only, so the WebGPU `render()` path is byte-unchanged).
