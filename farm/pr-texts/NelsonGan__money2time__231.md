# Stop full-app reloads and hidden-tab recomputation on common mutations

## Problem

Follow-up to #230 (this branch includes its commit; if #230 merges first this PR reduces to the second commit). A codebase-wide review for the same defect classes found three systemic render-path issues:

1. **Every non-transaction mutation ran `refreshAll()`.** A theme toggle, display-mode flip, account/category reorder, album activation, or wage edit synchronously re-ran the migration check, re-read **every table** (including the full transactions join with relations/splits), re-ran due recurring rules, re-synced notifications, and replaced every array and row identity — re-rendering all consumers with row-level memoization defeated.
2. **The `useApp()` value rebuilt on every transaction write.** `updateTransactionsBulk`, `deleteTransactionsBulk`, `queryTransactions`, the breakdown queries, and `getTransactionsByAccount` closed over the `transactions` array, so every write changed the whole context value identity — silently defeating the AppContext/TransactionsContext split that exists precisely to prevent this.
3. **Hidden tabs recomputed on every write.** The five main tabs stay mounted for the app's lifetime (`MountedTab`, opacity 0 when inactive), so a write on the calendar tab also re-ran the hidden Insights screen's full memo chain over all transactions, the hidden Settings profile-stats scan, and the hidden Accounts credit summaries — all behind the editor, during the bulk-create typing window.

## Changes

- **Scoped mutation refreshes** (`context/AppContext.tsx`): `runMutation` accepts an optional `refresh`; settings/display toggles refresh just the settings row, account + group ops refresh accounts/groups (+ balances only when they can change), category ops refresh categories, album create/delete/activate refresh albums, wage edits refresh wages. Mutations that change denormalized relation names on loaded rows (account/category renames, reassignment, redenomination) also refresh transactions. `refreshAll()` remains for load/retry, restores/imports/resets, mode switches, and recurring-rule edits (which rely on its `runDueTransactions` pass).
- **Identity-stable `useApp()` functions**: the transaction-touching functions now read render-synced refs instead of closing over state, so the context value no longer rebuilds per write. `getDisplayValueForTransaction` keeps its meaningful invalidation signals (display mode, wage history) but drops the per-write churn. AccountsScreen — the one consumer that relied on identity invalidation — now keys its memos on `useTransactions().transactions`.
- **Tab visibility** (`context/TabVisibilityContext.tsx`, new): `MountedTab` provides visibility; Calendar, Insights, Settings, and Accounts hold their last-seen transaction/balance snapshots via `useValueWhileTabVisible()` while hidden and catch up in a single recompute on activation. Root-stack screens (editors, drilldowns) default to visible and are unaffected.
- CLAUDE.md documents the new rules (narrowest refresh per mutation; memos over stable query functions must key on `useTransactions().transactions`).
