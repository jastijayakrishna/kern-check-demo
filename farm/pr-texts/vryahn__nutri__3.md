# fix(body): derive anthropometric indices from profile-scoped stature

## Summary

Retires `altura_cm` as a body measurement. Stature is a quasi-static anthropometric attribute scoped to the user — already persisted in the profile (`prefs.data.profile.height_cm`) — not a per-day datum. All derived indices (BMI, FFM, FFMI) now resolve stature from the profile, uniformly across the Medidas view and the Dashboard custom-chart pipeline.

## Motivation

Root cause: `buildDashSeries` derived FFMI strictly from row-local fields of `body_metrics.metrics`. A bioimpedance ingest (2026-07-14) landed without `altura_cm`, so every index derived from that row resolved to `null` and the Dashboard FFMI series truncated at the previous sample. The Medidas view masked the defect by carrying forward last-known stature from measurement history — an inconsistency between the two consumers of `derivedBodyMetrics`. Scoping stature to the profile removes the failure mode at its root rather than patching either call site.

This change is additionally required for correctness against the current production dataset: residual `altura_cm` keys have already been purged from `body_metrics` (backfill applied and verified — all 6 historical rows held 164, identical to the profile value; zero information loss). Code that resolves stature from measurement rows therefore renders every derived index as `null` in production today; this PR restores consistency between the deployed code path and the dataset.

## Implementation

- `src/lib/domain.js` — drop `altura_cm` from `BODY_METRICS` and `BODY_METRIC_MAX`; `derivedBodyMetrics(m, heightCm)` receives stature as an explicit argument; `buildDashSeries(..., heightCm)` threads it through to the derived-series resolver.
- `src/components/CustomChart.jsx` / `src/pages/Body.jsx` — inject `profile.height_cm`; Body no longer inherits stature from measurement history and renders a degraded-state caption (cause + action) when the profile lacks stature.
- `src/lib/importer.js` — retire the `height` / `height_cm` / `talla` CSV aliases; unrecognized columns are dropped by the existing unknown-column path.
- MCP `log_measurement` — rejects `altura_cm` by construction: input keys are validated against `BODY_METRICS`.
- Tests updated (`derivedBody.test.js`, `domain.test.js`); i18n: new degraded-state caption (es/en), orphaned `altura` key removed.

## Validation

- Both production users have `height_cm` set in their profiles (verified): no regression surface for derived indices.
- Dataset post-condition verified: 0 rows in `body_metrics` retain the `altura_cm` key.
