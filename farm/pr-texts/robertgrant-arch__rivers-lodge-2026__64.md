# Fix: resolve React Hooks violation in PropertyDetail booking-mode logic

## Summary

Fixes minified React error #310 ("rendered more hooks than during the previous render") that was thrown on the deployed member calendar (riverslodgehunt.com/portal/properties/11) after PR #62 merged.

## Root Cause

The `useEffect` hook added in PR #62 for auto-defaulting `selectedSlot` was called **after** early returns for `isLoading` and `error || !data`. This violates the Rules of Hooks — hooks must always be called at the top level before any conditional returns.

When the component loaded:
1. First render: all hooks called (including useEffect after the early return guard)
2. Re-render when data loads: early returns no longer trigger, useEffect now runs earlier
3. React detects mismatched hook count → throws error #310

## Solution (Option A)

Refactored to derive `activeSlot` synchronously instead of using `useEffect`:

1. **Move `useMemo`** (availableModes) to **before** early returns
   - Guards with `if (!data)` to return safe default while awaiting data

2. **Derive `activeSlot`** synchronously on every render:
   ```typescript
   const activeSlot = availableModes.includes(selectedSlot) 
     ? selectedSlot 
     : (availableModes[0] as "AM" | "PM" | "Overnight");
   ```

3. **Use `activeSlot` for all logic and rendering** (deterministic selection)
   - Keeps `setSelectedSlot` only in onClick handlers for user interaction
   - Ensures slot always matches available modes without side effects

4. **Removed the problematic `useEffect` entirely**
